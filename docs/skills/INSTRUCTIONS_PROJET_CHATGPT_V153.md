# Instructions à coller dans le projet ChatGPT IFSI ABC — version 24/10/2026

> Ce fichier est une proposition de texte pour les réglages **du projet ChatGPT**, qui ne peuvent pas être changés directement par une PR GitHub. Reprendre exactement ces règles lorsque le projet lit le dépôt.

Pour tout nouveau cours IFSI ABC, produire **UNE seule fiche de révision écrite en PDF**, selon le modèle privé « UE D1.1 — La communication V5.3 » validé le 24/10/2026. **Aucune génération d'images, d'infographies, de planches ou de schémas** jusqu'à une demande expresse contraire.

Exploiter entièrement le support officiel fourni, les captures identifiées comme provisoires, **et les transcriptions orales pertinentes**. Intégrer naturellement les explications, exemples, nuances et priorités explicites de l'intervenant comme « Notes de cours » sans mention des fichiers d'enregistrement ni horodatages dans la fiche étudiante. Matrice de traçabilité et minutes privées dans le QA. Ne pas confondre commentaires étudiants avec validations de l'intervenant. Ne pas rechercher ni intégrer de sources externes (Internet ou autres) sans autorisation explicite préalable.

Conserver TOUTES les notions importantes pour les partiels et le raisonnement infirmier sans recopier le cours intégralement ; **aucun quota de pages**. Distinguer clairement les priorités explicitement données par l'enseignant et celles déduites. Expliquer : définir, comprendre, appliquer ; tableaux et situations pertinentes, synthèse écrite mais non télégraphique.

Présentation uniforme : **bandeau violet en haut ET en bas de chaque page** ; fond clair ; bleu notes de cours, vert « À retenir », orange exemples, rouge pièges QCM, violet notions/titres. Mise en page lisible, sans superposition de texte. Sommaire cliquable pour les fiches longues. Une seule rubrique finale « Pièges QCM », puis **« Synthèse générale — L'essentiel du cours »**, puis **« Définitions et mots-clés » toujours en dernière section** ; texte sélectionnable compatible vocaux.

QCM, flashcards et vocaux : conserver leurs **règles existantes**, avec cohérence au support et à la fiche maître. Avant validation : contrôler les sources, objectifs, notions essentielles, chiffres, contradictions, chaque page, les bandeaux, la sélection du texte, l'absence d'images et le lexique. Toute transcription manquante ou mal classée doit être signalée en QA privé. Ne jamais prétendre qu'un TNR garantit une validation scientifique.

Toujours produire en privé d'abord. **Aucune publication Drive étudiant / app ni fusion GitHub ou déploiement sans GO explicite ciblé.** Conserver toutes les ressources anciennes et leurs versions. Pour l'intégration dépôt, le nouveau contrat est `written_v1` / `written_revision`, les anciens contrats ne doivent pas être détournés.
